# 高德地图 16.02.1 逆向分析报告

## 这个程序是干什么的
高德地图 iOS 客户端，内嵌 Alibaba DTHbalSe 安全 SDK 做设备指纹采集和风控检测，目标是通过 Hook 伪造设备身份、绕过风控、实现一键新机和登录态备份还原。

### 阶段四最终修复记录（2026-06-04）

| 修复项 | 根因 | 方案 |
|--------|------|------|
| 港号风控频繁 | CTCarrier 未伪装，每次新机运营商相同 | Tweak.x 新增 `%hook CTCarrier` 返回 profile 里的运营商；ProfileManager 随机生成三网运营商写入 active.json |
| 冷启动异常 | `__AMAP_APP_FIRST__` / `appInitMd5` 被 hook 拦截，每次启动触发"首次启动"逻辑 | 从 `defaultPrefSet` 和 `generateProfile` ud 列表中移除这两个 key；改由 ProfileManager 文件删除清理 |
| FINALPACKAGE 链接报错 | `__builtin___clear_cache` 在 block 中生成外部符号 `___clear_cache` | 改用 `sys_icache_invalidate`（`<libkern/OSCacheControl.h>`） |

### RT-4 验证关键发现
- **Keychain 存储格式**：`gd_amap/gd_amap` 存的是**二进制 UUID（16 字节）**，注入 UTF-8 UUID 字符串会导致 app 崩溃（格式错误）
- **正确新机策略**：所有 Keychain 条目全部 CLEAR（errSecItemNotFound），app 自动基于伪造 IDFV 重生成所有标识符
- **NSUserDefaults 底层**：iOS 16 的 `NSUserDefaults` 通过 `+resolveClassMethod:` 动态解析，不可在 spawn-paused 时用 `class_copyMethodList` 找到方法；改用 `CFPreferencesCopyAppValue` 拦截
- **spoof.js 崩溃根因**：`NSFileManager.defaultManager()` 在 spawn-paused 阶段调用 ObjC 单例方法会崩溃；改用 C `fopen`/`fread` 读档案文件

dev = frida.get_device('fcb0b05ae20229767149e98cb3ac94dcde52f74f')
pid = dev.spawn(['com.autonavi.amap'])
session = dev.attach(pid)
bypass = open('Reverse/output/scripts/frida/bypass.js', encoding='utf-8').read()
s = session.create_script(bypass)
s.on('message', lambda m,d: print(m))
s.load()
dev.resume(pid)
